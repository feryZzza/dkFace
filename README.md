# 人脸考勤 APP 课程设计说明

这是一个 C++11 控制台版人脸考勤 APP 模拟程序。程序分为服务端和客户端：服务端监听 TCP 端口并维护 `kaoqin.csv`，客户端把注册、打卡、工资查询、激励计划切换、删除等命令发送给服务端。

## 编译

依赖 OpenCV 4 和 Qt5 Widgets。OpenCV 用于摄像头采集和人脸检测，Qt 用于服务端和客户端图形界面。当前 CMake 会通过 `find_package(OpenCV REQUIRED)` 和 `find_package(Qt5 COMPONENTS Widgets REQUIRED)` 查找本机依赖。

```bash
cmake -S . -B build
cmake --build build
```

生成的可执行文件为：

```bash
./build/main
./build/server_gui
./build/client_gui
```

## 运行方法

### 图形化界面

推荐先启动服务端界面，再启动客户端界面：

```bash
./build/server_gui
./build/client_gui
```

服务端界面可以启动/停止监听、设置服务端统一打卡日期和时间、按工号查询任意员工情况、查看 `kaoqin.csv` 中的全部考勤记录，并实时显示客户端请求日志。客户端界面提供员工注册、手动打卡、人脸录入、刷脸打卡、刷脸查询工资、激励计划切换和删除员工等入口。

### 命令行界面

先启动服务端。打卡日期和打卡时间都可以由服务端统一决定，测试时可以在服务端启动参数中指定 2026 年内的日期和时间：

```bash
./build/main server 9102 2026-05-12 08:50
```

服务端运行后，也可以直接在服务端窗口输入命令修改后续打卡日期和时间：

```text
date 2026-06-01
time 09:10
now 2026-06-01 07:20
query 1001
list
```

再打开另一个终端进入菜单式客户端：

```bash
./build/main client 127.0.0.1 9102
```

客户端会显示数字菜单，按编号选择功能，再输入必要内容即可：

```text
========== 人脸考勤系统 ==========
1. 员工注册
2. 手动打卡
3. 录入人脸
4. 刷脸打卡
5. 刷脸查询工资
6. 加入激励计划（需刷脸确认）
7. 退出激励计划（需刷脸确认）
8. 删除员工（需刷脸确认）
0. 退出
```

如果要使用摄像头刷脸，通常先选择 `3. 录入人脸`，再选择 `4. 刷脸打卡`。

仍然支持一行命令快速调用，适合调试：

```bash
./build/main client register 1001 张三
./build/main client mark 1001 张三 08:50
./build/main client face_register 1001 张三
./build/main client face_mark 08:50
```

## 菜单说明

- `1. 员工注册`：输入工号和姓名，创建或更新员工信息。
- `2. 手动打卡`：输入工号、姓名和可选时间；若服务端设置了打卡时间，则优先使用服务端时间，打卡日期使用服务端设置的日期。
- `3. 录入人脸`：输入工号和姓名，调用摄像头保存多帧人脸样本。
- `4. 刷脸打卡`：输入可选时间，调用摄像头识别员工，识别成功后自动打卡；若服务端设置了打卡时间，则优先使用服务端时间。
- `5. 刷脸查询工资`：调用摄像头识别员工，识别成功后自动查询工资。
- `6. 加入激励计划`：输入工号后调用摄像头刷脸确认，识别工号一致才切换到激励计划。
- `7. 退出激励计划`：输入工号后调用摄像头刷脸确认，识别工号一致才恢复普通计划。
- `8. 删除员工`：删除前需要文字二次确认和刷脸确认，识别工号一致后删除员工记录和对应照片模板。

查看全部考勤记录只能在服务端窗口输入 `list`，查询指定员工情况可以在服务端输入 `query 工号`，客户端不提供按工号直接查询功能。

## 功能对应

- `face_register`：调用摄像头检测人脸，保存 `photos/工号.png` 主模板和 `photos/工号/` 多帧样本，然后向服务端注册员工。
- `face_mark`：调用摄像头识别人脸，识别成功后自动发送 `CLIENT_MARK` 打卡消息。
- `face_query`：调用摄像头识别人脸，识别成功后自动发送 `CLIENT_QUERY` 查询工资消息。
- `CLIENT_PING`：客户端测试服务端连通性，只返回服务状态，不读写员工考勤数据。
- `CLIENT_TIME_STATUS`：客户端同步服务端当前打卡日期和时间设置，只读取状态，不读写员工考勤数据。
- `CLIENT_MARK`：打卡。普通员工 9:00 前有效，超过时间记缺勤；打卡日期由服务端统一设置，服务端时间覆盖客户端时间。
- `CLIENT_QUERY`：查询工资。工资分段结算：普通阶段始终按 `勤奋数 * 500 - 缺勤数 * 300`，激励阶段始终按 `勤奋数 * 1000 - 缺勤数 * 1000`，再加当前计划基础工资。
- `CLIENT_HARDWORK`：加入激励计划。客户端刷脸确认后发送，打卡时间改为 7:00，基础工资改为 8000，奖惩金额改为 1000。
- `CLIENT_NORMAL`：退出激励计划。客户端刷脸确认后发送，恢复普通计划的打卡时间和工资规则。
- `CLIENT_DELETE`：客户端刷脸确认后发送，删除员工在 `kaoqin.csv` 中的记录，并删除 `photos/` 下以该工号开头的照片文件。

## 打卡规则

普通计划：

- 9:00 前打卡成功。
- 9:00 及以后打卡，缺勤次数加一。
- 已有缺勤时，8:00 前打卡可补救一次缺勤。
- 7:30 前打卡算勤奋奖励一次，并在有缺勤时减少一次缺勤。
- 缺勤达到 5 次后不能继续打卡。

激励计划：

- 7:00 前打卡成功。
- 7:00 及以后打卡，缺勤次数加一。
- 6:30 前打卡算勤奋奖励，并可减少一次缺勤。
- 激励阶段新产生的勤奋和缺勤按 `勤奋数 * 1000 - 缺勤数 * 1000` 结算。
- 加入激励计划前已经产生的普通勤奋和普通缺勤仍按 `勤奋数 * 500 - 缺勤数 * 300` 结算，不会改按1000元计算。

## 代码结构

- `main.cpp`：程序入口，只负责区分 `server` 和 `client` 模式。
- `include/attendance.hpp`：考勤业务接口，向服务端暴露 `processRequest()`。
- `src/attendance.cpp`：核心业务逻辑，包括 CSV 读写、打卡判断、工资计算、计划切换和删除。
- `include/client.hpp` / `src/client.cpp`：客户端命令解析和 TCP 请求发送。
- `include/face_recognition.hpp` / `src/face_recognition.cpp`：OpenCV 摄像头采集、Haar 人脸检测、LBPH 模板录入和多帧匹配。
- `include/server.hpp` / `src/server.cpp`：服务端监听、接收客户端连接并调用考勤业务模块。
- `src/server_gui.cpp`：Qt 服务端图形界面，封装可启动/停止的 TCP 监听、时间设置、记录查看和服务日志。
- `src/client_gui.cpp`：Qt 客户端图形界面，封装注册、打卡、刷脸、计划切换和删除等用户操作。

## 简易人脸识别说明

程序使用 OpenCV 的 Haar 级联模型检测摄像头画面中的人脸。录入时会连续采集 5 张稳定人脸样本，截取最大的人脸区域，转灰度、缩放、均衡化后保存；识别时会采集 3 张当前人脸，使用 OpenCV LBPH 人脸识别器和已保存模板匹配，并要求多帧投票结果一致且平均匹配分数低于阈值才认为识别成功。

LBPH 比直接比较灰度像素更能适应轻微光线、位置和表情变化，但仍建议录入和打卡时保持光线稳定，并正对摄像头。匹配分数越低表示越相似，默认阈值在 `src/face_recognition.cpp` 的 `MATCH_THRESHOLD` 中配置。

默认人脸检测模型路径为：

```text
/usr/share/opencv4/haarcascades/haarcascade_frontalface_default.xml
```

如果运行时提示无法打开摄像头，请检查摄像头是否被占用、系统权限是否允许访问摄像头。

如果摄像头已经识别成功但没有打卡结果，请确认服务端已经启动，并且客户端连接的 IP 和端口正确。客户端网络收发设置了 5 秒超时，服务器无响应时会返回“等待服务器响应超时或服务器无响应”，不会一直卡住。

## 协议格式

客户端和服务端之间使用简单文本协议：

```text
消息类型|工号|姓名|时间
```

例子：

```text
CLIENT_MARK|1001|张三|08:50
CLIENT_QUERY|1001||
CLIENT_HARDWORK|1001||
CLIENT_DELETE|1001||
```

客户端支持 `raw` 命令直接发送协议消息：

```bash
./build/main client raw 'CLIENT_MARK|1001|张三|09:10'
```

`raw` 不允许发送 `CLIENT_HARDWORK`、`CLIENT_NORMAL`、`CLIENT_DELETE`、`CLIENT_LIST`。激励/删除必须走客户端命令或菜单并完成刷脸确认；查看全部考勤记录只能在服务端输入 `list`。
